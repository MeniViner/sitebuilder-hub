# Dashboard Direction Reset Audit

Date: 2026-07-06

## Purpose

This audit documents why the previous dashboard explorations did not yet find the right direction for Site Builder Hub, and what the next dashboard direction must feel like before any promotion discussion.

The production dashboard at `#/` remains unchanged.

## Why The Original Dashboard Lab Failed

The original Dashboard Lab was useful as a data exercise, but it did not break far enough from the existing product rhythm.

- It stayed too close to the same AppShell mental model.
- It reused the same admin-console density and old card rhythm.
- It repeated the same status-chip language instead of creating a clearer decision surface.
- It looked like another internal registry screen, not a daily-use dashboard.
- It leaned on broad KPI grids and module-style panels.
- It made the dashboard feel like the old product reorganized, not a new product-quality first screen.
- It did not give the user a strong enough answer within five seconds: what is the posture, what matters most, and where should I click?

## Why The North Star Attempt Failed

The detached route was the right architectural move, but the visual direction was wrong.

- It looked too sci-fi and generated.
- The large pulse/ring was decorative and not specific enough to managing Site Builder sites.
- Dark glass treatment became a style layer instead of a product language.
- It had drama, but not enough calm daily usability.
- The Hebrew copy felt attached to the visual gimmick rather than native to the product.
- It looked like a concept shot, not a dashboard an operator or manager would open every morning.
- It was detached from AppShell, but not yet grounded in the human workflows: Deploy, Recovery, Access, Health, and site inspection.

## What A Good Site Builder Hub Dashboard Needs To Feel Like

A good Site Builder Hub dashboard should feel:

- Human: written for a person making decisions, not for a generic “operations command” fantasy.
- Operational: clear about what can run, what is blocked, and which domain needs attention.
- Premium: composed, intentional, and visually confident.
- Calm: no false alarms, no decorative panic.
- Clear: top issue, next action, and current posture are visible immediately.
- Credible: no fake history, no invented topology, no decorative analytics.
- Useful in the morning: strong first fold, short reading path, direct links to the right deep pages.
- Product-specific: sites, environments, storage backends, backup freshness, version readiness, capabilities, and domain readiness should shape the design.

## Banned List

Do not use these as the main direction:

- Old AppShell.
- Old top bar or right rail.
- Old card grid and old KPI cards.
- Giant meaningless donut/pulse.
- Cyber/neon overload.
- Fake sci-fi dashboard language.
- Generic dark glassmorphism.
- Endless KPI grids.
- Module directory panels.
- Status-pill soup.
- Raw technical evidence on the homepage.
- Raw JSON.
- Fake line charts or invented trends.
- Fake topology edges.
- Long diagnostic explanations.

## Direction Reset

The next sprint should not polish the North Star screen. It should create four distinct lab-only artboards outside AppShell:

- Morning Brief: a human executive opening page.
- Operations Board: an action-first operator board.
- Fleet Map: a product-specific map of real sites.
- Clean Bento Analytics: a modern SaaS analytics composition using only honest snapshot visuals.

None of these should be promoted until real screenshot/manual visual QA proves that one direction is worth refining.
